# Verified current and confirmed Python 3.13-compatible as of July 2026.
# NOT 3.14: vLLM's dependency tree (flashinfer cuda-tile, ray, numba <0.63,
# outlines-core <0.2.14) lacks cp314 wheels — vllm-project/vllm#34096.

# GPU NOTE — on Windows, `pip install torch` gives the CPU-ONLY build
# (version shows as e.g. "2.11.0+cpu" and torch.cuda.is_available() is False).
# For NVIDIA GPU support install from the CUDA wheel index instead, e.g.:
#   pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
# (pick the cuXXX tag matching your driver; see pytorch.org/get-started).
# On Linux the default PyPI wheel already bundles CUDA. The harness prints a
# loud warning at startup if it detects a CPU-only install.
#
# torch is pinned EXACTLY, together with vllm below, because vllm 0.25.1
# declares torch==2.11.0 (per its PyPI metadata). Installing vllm next to a
# different torch is what caused three separate CUDA-runtime failures in one
# session (libcudart.so.13 / libnvrtc.so.13 / libnvJitLink.so.13): unpinned
# `pip install vllm` pulled CUDA-13 wheels in beside a cu128 torch install.
# See stage2_vllm_task.md (Task 4). Bump these two pins together, resolved
# from the same index in the same pip run, or not at all — same reasoning
# as the pinned model revisions in config.py: reproducibility.
# (Note: this moves the container's torch from >=2.13 to ==2.11.0 for the
# HF path too; torch 2.11.0 ships cp313 wheels for the python:3.13-slim base.
# If strict numeric continuity with earlier HF-path container runs matters,
# re-run the HF smoke test before comparing across runs.)
torch==2.11.0

# vLLM: batched inference engine for the Stage 2 path (INFERENCE_ENGINE=vllm
# in evaluation/run_baseline.py). 0.25.1 is the version validated on real
# weights for all four models. The vllm wheel is abi3 (>=3.10,<3.15), but its
# DEPENDENCIES cap the container at Python 3.13 — see vllm-project/vllm#34096
# and the Dockerfile base-image comment.
vllm==0.25.1
transformers>=5.13
accelerate>=1.0
sentence-transformers>=3.3
datasets>=3.0
langchain>=0.3
langchain-community>=0.3
huggingface_hub>=0.28
numpy>=2.1

# faiss-cpu: compiled C++ extension. Linux cp313 wheels are confirmed end to
# end for the python:3.13-slim base (this was "Option B" of the old cp314
# caveat, now moot — the base image dropped to 3.13 for vLLM's dependency
# tree anyway; see vllm-project/vllm#34096). The Dockerfile still installs
# swig + libopenblas-dev as source-build insurance.
faiss-cpu>=1.13.2

# NOTE: the `runpod` SDK is deliberately NOT listed here. It cannot coexist
# with vllm: runpod 1.11.0 requires fastapi>=0.139.2 while vllm 0.25.1 caps
# fastapi<0.137.0, and fastapi is a hard (non-extras) dependency of runpod, so
# there is no pip-level way to install it without the web stack. A full
# `pip install -r requirements.txt` fails outright on those two ranges.
# scripts/run_and_terminate.py therefore calls RunPod's REST terminate
# endpoint (DELETE https://rest.runpod.io/v1/pods/{podId}) directly via
# `requests`, which vllm already pulls in transitively (requests>=2.26.0).
# No new package, no new conflict surface.
